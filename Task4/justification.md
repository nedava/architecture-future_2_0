# Обоснование конфигурации Terraform для Yandex Cloud

## Выбор ресурсов и параметров

### Вычислительные ресурсы

- VM-1: 2 vCPU, 2 ГБ RAM
- VM-2: 4 vCPU, 4 ГБ RAM

Дифференциация ресурсов: две разные конфигурации выбраны для демонстрации

 - VM-1 (2vCPU/2GB): Подходит для легких задач (веб-сервер, прокси, мониторинг)
 - VM-2 (4vCPU/4GB): Для более ресурсоемких приложений (база данных, приложение с высокой нагрузкой)

Экономическая эффективность: оптимальны для тестовых сред. Минимальные конфигурации снижают стоимость при разработке 
и тестировании.

Масштабируемость: использование переменных для ресурсов позволяет легко изменять параметры, поддержка вертикального 
масштабирования через изменение переменных.

### Дисковое пространство

- Тип: network-hdd (сетевой HDD)
- Размер: 15 ГБ для каждой VM

network-hdd наиболее экономичный вариант для тестовых сред. Подходит для ОС и приложений без высоких требований к IOPS.
При необходимости можно легко перейти на network-ssd.

Размер диска 15 ГБ достаточно для Ubuntu 22.04 LTS (~8 ГБ) + резерв для приложений. Позволяет устанавливать Docker,
контейнеры и необходимое ПО. Легко увеличивается через изменение переменной disk_size.

### Сетевая конфигурация

- VPC: Изолированная виртуальная сеть
- Subnet: 192.168.10.0/24 (256 адресов)
- NAT: Включен для обеих виртуальных машин

/24 подсеть - оптимальный размер для тестовой среды, имеет достаточно адресов для расширения (добавления новых ВМ).

Преимущества NAT Gateway:
- Автоматическое получение внешних IP
- Безопасность. Внутренние адреса скрыты за NAT
- Экономия. Динамические IP обычно бесплатны или дешевле статических

Зона доступности ru-central1-a - основная зона с хорошей доступностью.


## Преимущества декларативного подхода

Идемпотентность. Многократное выполнение terraform apply дает одинаковый результат. Terraform автоматически определяет,
какие изменения необходимы.

Сравнение состояний. Terraform сравнивает текущее и желаемое состояние и реальные ресурсы облака.

Автоматическое разрешение зависимостей. Terraform автоматически определяет порядок: сначала создается VPC, затем Subnet,
потом VM.

IaC решает проблему воспроизводимости, когда каждый сервер настраивается вручную и имеет уникальную конфигурацию.
Проблема решается через версионирование и документирование в коде (самодокументирующийся код в .tf), тестирование
инфраструктуры в разных средах путем выбора значения переменной (-var environment=dev/stage/prod).

Также IaC решает проблему масштабирования: горизонтальное масштабирование с помощью указания количества инстансов через
переменные, а также вариант с автомасштабированием (интеграция с системами автоскейлинга).

Iac имеет экономические и операционные преимущества: автоматизация рутинных задач и оптимизация ресурсов, ускорение
развертывания.
