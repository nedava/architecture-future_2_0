# Задание 3. Разработка технологического радара и роадмапа изменений для поддержки бизнес-целей компании

## Технологический радар

Чтобы локально запустить техрадар необходимо из директории Task3/tech-radar:

1. Выполнить команду установки зависимостей yarn:
```shell
yarn
```

2. Запустить локальный сервер:
```shell
yarn start
```

3. После этого должен автоматически запуститься браузер и открыть страницу с радаром по адресу:
```
http://localhost:3000/
```

Ниже представлены технологии, платформы, методологии из техрадара и бизнес-сценарии, которые они поддерживают.

## Языки и технологии 

### Adopt

- Python - ИИ-сервисы, ETL, аналитика
- FastAPI - API портала для сервисов на Python
- React + TypeScript - Веб-интерфейсы портала, замена PowerBuilder
- Java Spring Boot - Backend API, интеграционные сервисы
- Go - Высоконагруженные финтех-сервисы

### Trial

- Spark + Scala - Обработка больших данных, ETL в масштабе
- Rust - Критичные по производительности сервисы
- Kotlin - Backend для Android приложений

### Assess

- WebAssembly (WASM) - Вычисления на клиенте, тяжелая аналитика в браузере
- Julia - Научные вычисления, сложная математика для ИИ
- Elixir/Phoenix - Real-time системы, чаты, уведомления
- Deno/Node.js - Быстрые прототипы, BFF слой


### Hold

- PowerBuilder - Устаревший, дефицит специалистов, плохой UX
- Legacy .NET Framework (< 4.8)
- JQuery + устаревший JS


## Платформы

### Adopt

- AWS/Azure/GCP - Гибкость, снижение TCO, managed services
- GitHub/GitLab - Все проекты, документация, код-ревью
- Kubernetes - Автомасштабирование, отказоустойчивость, портативность

### Trial

- Trino - Распределённые SQL запросы
- Minio - Единое S3-совместимое хранилище
- MLflow - Управление ML lifecycle: эксперименты, deployment моделей
- ArgoCD - GitOps для Kubernetes. Автоматизация deployment

### Assess

- Snowflake - Управляемое DWH в облаке
- Databricks - Unified analytics platform
- OpenLineage - Полное отслеживание происхождения данных


### Hold

- On-prem VMware инфраструктура	- Дорого, сложно масштабировать
- Physical сервера - Высокие капитальные и операционные расходы, низкая гибкость	
- Legacy SAN/NAS - Дорого, сложное управление
- SQL Server 2008 - Нет поддержки, security риски, масштабирование


## Инструменты

### Adopt

- Apache Airflow - Оркестрация ETL/ELT, кросс-доменные пайплайны
- Apache Kafka - Event-driven архитектура, потоковая обработка
- Git + GitHub Actions - Управление кодом, CI/CD, совместная разработка
- Docker + Docker Compose - Контейнеризация
- Terraform - IaC, воспроизводимость, версионность инфраструктуры


### Trial

- Apache Iceberg - Хранение аналитических данных
- DataHub - Каталог данных для самообслуживания
- Nessie - Версионность данных для ИИ/DS
- Cube.js - Семантический слой для отчётов	

### Assess

- Great Expectations - Контроль качества данных
- Flyway/Liquibase - Миграции схем БД
- dbt (Data Build Tool) - Трансформации в ELT пайплайнах
- Prefect - Альтернатива Airflow для оркестрации

### Hold

- SQL Server Integration Services - сложно масштабировать, ограниченная функциональность
- Apache Camel (как ESB) - Сложность, устарело, плохая поддержка streaming


## Техники и подходы

### Adopt

- Agile/Scrum - Быстрая адаптация к изменениям, прозрачность
- CI/CD Pipelines - Качество кода, скорость доставки, уменьшение рисков
- Infrastructure as Code - Воспроизводимость, безопасность, контроль версий
- Microservices Architecture - Независимое развертывание, масштабирование


### Trial

- Data Mesh - Для независимого развития доменов
- Event-Driven Architecture - Слабая связанность доменов, масштабируемость, отказоустойчивость
- GitOps - Версионность и воспроизводимость
- MLOps - ИИ для диагностики, прогнозирование

### Assess

- FinOps - Управление облачными затратами
- Platform Engineering - Внутренние платформы разработки
- Data Contracts - Стандартизация обмена данными


### Hold

- Waterfall разработка - Медленно, негибко, высокий риск
- Big Bang миграции - Высокий риск, возможные простои
- Manual deployment - Ошибки, непоследовательность
- Monolithic Architecture - Невозможность независимого развития
